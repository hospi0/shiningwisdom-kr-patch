## ETC 구조 (M001.ETC 기준, 적재 0x060BC000)
- 진입 0x060BC00C 초기화가 **맵 머리말 주소 → 전역 0x0602FFF8** (M001: 0x060C4A3C = 파일 0x8A3C).
- 머리말: +00 글꼴 · +04 허프만 트리쌍 표 · +08 ? · +0C ? · +10 ? · +14‥+40 함수 포인터(이벤트 콜백, X04 가 `@(40,Rn)` 등으로 호출).
- **글꼴**: [u16 폭][u16 × 15줄] = 32 B/글자, 16px 폭 1bpp(가변폭, 12px 안팎). 코드 c → 글꼴 + (c−0x20)×32.
  - 0x20‥0x7E ASCII · 0x86‥0x9F 히라가나(を ぁ…っ · あ…そ) · 0xA1‥0xDF 가타카나(JIS X0201 순) · 0xE0‥0xFD 히라가나(た…ん) · **0x100‥ 한자 = 맵마다 다름**(그 맵에 쓰는 것만, 맵별 총 393‥689칸). 0x20‥0xFF 부분은 모든 ETC 동일.
  - 42개 ETC 모두 글꼴을 가짐 → 한글도 «맵별 필요 음절만» 넣는 구조로 갈 수 있음(수용량은 맵별 ETC 크기·적재 공간이 한계).
- **대사 압축(확정)**: 직전 바이트별 허프만 트리 256개. 트리쌍 표 = u32 절대주소 × 512 = (잎 기호 목록 주소, 트리 모양 비트 주소). 트리 = 전위 순회, 비트 1 = 잎(잎 기호는 목록 순서), 0 = 내부 노드(왼쪽=0). 쓰이지 않는 직전 바이트는 null → M001 256개 중 240개 정확히 풀림(잎 수·비트 길이 일치).
  - 풀린 기호는 **u16 글자 코드의 바이트 쌍**(`xx 00/01` 꼴) — 대사 = u16 BE 코드를 바이트 단위로 허프만 압축.
- ✅**문장 위치 확정(2026-10-04, 스테이트 3 = M061 적재)**: 해독 루틴 X02 0x0605A54C(문장 번호 R4). 머리말 +08 = 묶음 표(u32 절대, 0 끝 — 지금까지 모든 ETC 1묶음). 묶음[id>>8] 에서 [길이 바이트][비트열]을 id&0xFF 번 건너뜀 → 비트열 = 직전 바이트 0 · 마스크 0x80(MSB 먼저) · u16 0x0000 끝. 상태 변수 0x0605E947(직전 바이트)·0x0605E948(바이트 포인터)·0x0605E94C(비트 마스크).
  - 검증: 화면 「おじいさんのことを 心配だから / 迷ってるの・・・やさしい子ね」 = M061 79번(0x727F, `0002` 머리) — RAM 해독 버퍼 0x0605E53A 와 같음. M061 107문장 전부 «쓴 바이트 = 길이 바이트».
  - 제어(사용 빈도): 0002(658, 문장 머리) · 0003 줄바꿈(5961) · 0005 창 넘김(314) · 0008(3164, 끝 대기?) · 000A(961) · 0015(862, 뒤에 인자 0002 등) · 0004·0006·0007·0009·000E·0010·0001 — 뜻은 다음 단계.
  - 탁점·반탁점은 따로 붙는 글자(し+゛). 0x0100 = 맵 한자 0번이 아니라 «변수 삽입» 후보(「データを{0100}…」).

## 글꼴 공간 (2026-10-04, 2번)
- ETC 자리 = 0x060BC000‥0x060D0000(80KB). 바로 뒤 0x060D0000·0x060E8000 = MAP 버퍼(MAP 최대 155KB) → 하이 RAM 여유 없음. 맵별 ETC 여유는 M039 176B · M030 824B ~ 최대 56KB.
- 맵별 글꼴칸(0x20~) 361‥657, 한자칸 137‥433.
- ★**LowRAM 0x00284000‥0x002E0000(약 360KB)이 스테이트 s1·s3·s4 모두 비어 있음.** 글꼴 위치 = 머리말 +00 포인터 하나 → 게임 전체 한글 음절 한 벌(예 2,000자 × 32B = 64KB)을 LowRAM 에 두고 맵 머리말 +00 만 돌리면 맵별 공간 문제 없음. ⏳확인: ①전투·보스·컷신 등 다른 장면에서도 빈지(스테이트 더) ②누가 거기에 글꼴을 올리나(부팅 때 읽는 파일에 덧붙이거나 적재 코드 추가) ③렌더러가 LowRAM 읽기 가능(CPU 그리기라 가능할 것).
